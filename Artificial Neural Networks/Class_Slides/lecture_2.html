Overview

This lecture moves from Lecture 01's broad "what is ML/deep learning" orientation into the first concrete computer-vision task: image classification — assigning a label to an image from a fixed set of categories. It covers what an image "looks like" to a computer, the vocabulary used throughout the rest of the course (dataset, data point, training/testing/validation sets, hyperparameters), the real-world challenges that make the task hard, the four-step pipeline for building a deep learning classifier, and how feature-based (traditional) machine learning differs from end-to-end deep learning.

Why this matters: Image classification is the running example for the entire course. The vocabulary introduced here — training/testing/validation splits, hyperparameters, overfitting risk from class imbalance — will be reused constantly once the course reaches actual neural network architectures.

  • List and describe the seven common challenges in image classification (viewpoint, scale, deformation, occlusion, illumination, background clutter, intra-class variation).

  • Explain why train/test sets must never overlap, and why a separate validation set is needed for hyperparameter tuning.
  • Compare traditional feature-based machine learning (hand-engineered features + classifier) with end-to-end deep learning (CNNs that learn their own features).

Big Picture

Image classification sits as one concrete application inside the hierarchy from Lecture 01. This lecture essentially zooms into the "Model Learning" and "Model Testing" boxes of the general ML pipeline you already studied, and shows exactly what they look like for images:

What Is Image Classification?

From your lecture

🟢 Simple Explanation

A computer doesn't "see" a cat or a dog the way you do. It only sees a huge grid of numbers (pixel brightness values). Image classification is the job of turning that grid of numbers into a single label, like "cat."

🔵 Technical Explanation

Per the lecture: "For computers, interpreting the contents of an image is less trivial — all our computer sees is a big matrix of numbers. It has no idea regarding the thoughts, knowledge, or meaning the image is trying to convey." Image classification is formally defined as "the task of assigning a label to an image from a predefined set of categories."

Why Do We Need It?

To go from "a grid of numbers" to "this image contains a cat," we need computer vision and machine learning algorithms that can extract meaning from raw pixels. Per the lecture, this could be as simple as assigning one label, or as advanced as generating a full human-readable sentence describing the image — and "image classification and image understanding are currently (and will continue to be) the most popular sub-field of computer vision for the next ten years."

The Formal Setup

🟣 Mathematical / Computational View

Given an input image of W × H pixels with three color channels (Red, Green, Blue), the image is really a W × H × 3 = N pixel array of numbers. The goal of image classification is to take that N-number array and correctly assign a label from a predefined category set — for example categories = {cat, dog, panda}.

Symbol Meaning Example
W Image width in pixels e.g. 224
H Image height in pixels e.g. 224
3 Number of color channels (R, G, B) Red, Green, Blue
N = W × H × 3 Total number of pixel values fed to the classifier 224×224×3 = 150,528

Terminology

From your lecture

These terms recur throughout the rest of the course, so it's worth locking them in now.

Term Definition (from the lecture)
Dataset A collection of data points we are trying to extract knowledge from.
Data point Each individual example/item in the dataset (an image, a piece of text, an audio clip, etc.).
Image dataset (special case) In image classification, the dataset is a collection of images, so each image is one data point.

🔵 Connection

This vocabulary is deliberately general — "data point" applies whether you're working with images, text, or audio — because the same machine learning pipeline concepts (train/test/validate) apply across all of them.

Challenges in Image Classification

From your lecture

The lecture lists seven challenges that make image classification hard even for the same object category:

Challenge What It Means
Viewpoint variation The same object looks completely different from different camera angles.
Scale variation The same object can appear at very different sizes in the image.
Deformation Many objects (bodies, toys, animals) can bend or change shape while staying the same category.
Occlusion Part of the object is hidden behind something else, e.g. a dog partly covered by a blanket.
Illumination Lighting conditions (bright vs. dim) change how the object's pixels look.
Background clutter The object can blend into a busy, visually noisy background.
Intra-class variation Objects in the same category can look very different from one another (e.g. many different styles of "chair").

🔵 Why This Matters

A good image classifier has to be robust to all seven of these variations at once — it can't just memorize what one photo of "cat" looks like; it has to generalize across viewpoint, scale, lighting, clutter, and the natural variety within a category.

A Shift in Mindset

From your lecture

Before introducing the pipeline, the lecture makes an important point about why deep learning is a different way of programming altogether.

Traditional (Procedural) Programming

>>> def fib(n):
...     if n == 0:
...         return 0
...     elif n == 1:
...         return 1
...     else:
...         return fib(n-1) + fib(n-2)
...

This kind of function: accepts an input, returns an output, follows a well-defined process, and its output is easily verifiable for correctness — it lends itself well to code coverage and test suites.

The catch: "Unfortunately, this is not the case for deep learning and image classification!"

Why Rule-Writing Doesn't Work For Images

The lecture poses a thought experiment: imagine trying to write a procedural function that tells the difference between a photo of a cat and a photo of a dog. Would you check individual pixel values at various (x, y) coordinates? Write hundreds of if/else statements? And how would you maintain and verify the correctness of such a massive rule-based system?

The lecture's answer: "The short answer is: you don't." Instead of hand-writing rules, we let a deep learning model learn the rules from labeled examples — which is exactly why the four-step pipeline below exists.

The Four-Step Deep Learning Classification Pipeline

From your lecture

This is the practical, step-by-step recipe for building a deep learning-based image classifier.

Step 1: Gather Your Dataset

🔵 What Happens

You collect the images that make up your categories. A key risk here is class imbalance: "If we have twice the number of cat images than dog images, and five times the number of panda images than cat images, then our classifier will become naturally biased to overfitting into these heavily-represented categories." Class imbalance is a common problem in machine learning, and there exist a number of ways to overcome it.

Step 2: Split Your Dataset

Once you have your dataset, it must be split into independent parts:

Split Purpose
Training set Used by the classifier to "learn" what each category looks like — it makes predictions and corrects itself when wrong.
Testing set Used only after training, to evaluate the classifier's performance on unseen data.
Validation set A third split, usually carved out of the training data (~10–20%), used as "fake test data" to tune hyperparameters — before touching the real testing set.

⚠️ Precaution

"It's extremely important that the training set and testing set are independent of each other and do not overlap! If you use your testing set as part of your training data, then your classifier has an unfair advantage since it has already seen the testing examples before and 'learned' from them." The testing set must be used only to evaluate the final network — never to train or tune it.

Hyperparameters and the Validation Set

🔵 Why a Third Split Is Needed

Neural networks have "knobs and levers" — e.g. learning rate, decay, regularization — called hyperparameters, which must be tuned carefully. You might be tempted to use the testing set to tweak these values, but per the lecture, "this is a major no-no!" The test set is only used to evaluate final performance. Instead, a validation set (normally carved from the training data) is used to tune hyperparameters. Only after hyperparameters are chosen using the validation set do you move on to collecting final accuracy results on the testing set.

Step 3: Train Your Network

Given the training set, the network learns to recognize each category in the labeled data. "When the model makes a mistake, it learns from this mistake and improves itself."

Step 4: Evaluate

For each image in the testing set, the network predicts a label. These predictions are compared against the ground-truth labels (what the image category actually is). From this comparison, we compute the number of correct predictions and aggregate metrics such as precision, recall, and f-measure, which quantify overall classifier performance.

Step One-line Summary
1. Gather Your Dataset Collect images per category; watch for class imbalance.
2. Split Your Dataset Separate into training / validation / testing; never mix testing into training.
3. Train Your Network The network learns from mistakes on the training set.
4. Evaluate Compare predictions to ground truth using precision, recall, f-measure.

Feature-Based Learning vs. Deep Learning

From your lecture

🟢 Simple Explanation

In the older approach, a human decides in advance what patterns (shape, color, texture) to look for in an image, then a classifier learns from those hand-picked patterns. In deep learning (specifically CNNs), the network is fed the raw pixels directly and figures out on its own which patterns actually matter.

🔵 Technical Explanation

Per the lecture: in the traditional, feature-based approach, an extra step is inserted between Step #2 (split dataset) and Step #3 (train) — feature extraction. Hand-engineered algorithms such as HOG (Histogram of Oriented Gradients) and LBPs (Local Binary Patterns) are applied to quantify a particular component of the image (shape, color, texture). Only after this feature extraction step do we train and evaluate the classifier.

When building Convolutional Neural Networks (CNNs), the feature extraction step can be skipped entirely, because CNNs are end-to-end models: raw pixel data is presented directly to the network, which learns filters inside its hidden layers to discriminate between object classes. The output is a probability distribution over class labels.

Aspect Feature-Based (Traditional) End-to-End Deep Learning (CNN)
Input to classifier Hand-engineered features (e.g. HOG, LBPs) Raw pixel data
Who designs the features A human engineer The network itself (learned filters)
Extra pipeline step Feature extraction, between splitting and training None — end-to-end
Output Classifier decision based on extracted features Probability distribution over class labels

The tradeoff: "One of the exciting aspects of using CNNs is that we no longer need to fuss over hand-engineered features — we can let our network learn the features instead. However, this tradeoff does come at a cost. Training CNNs can be a non-trivial process, so be prepared to spend considerable time familiarizing yourself with the experience and running many experiments to determine what does and does not work."

⚠️ Common Beginner Mistakes

Mistake: Using the testing set to tune hyperparameters

Why people make it: It feels efficient to just check performance on the "real" test set while adjusting settings.

Correct understanding: This contaminates your evaluation — the lecture explicitly calls this "a major no-no." Use a separate validation set for tuning, and touch the testing set only once, at the very end.

Mistake: Ignoring class imbalance when gathering data

Why people make it: It's easy to collect whatever images are most available (e.g., far more cat photos than panda photos).

Correct understanding: Heavily imbalanced categories naturally bias the classifier toward overfitting to the majority classes — this needs to be addressed deliberately.

Mistake: Assuming deep learning always skips feature engineering entirely

Why people make it: "End-to-end" sounds like there's no design work at all.

Correct understanding: CNNs skip hand-engineered features, but they still require careful architecture design and hyperparameter tuning — the lecture is explicit that "training CNNs can be a non-trivial process."

Mistake: Thinking a classifier just needs to memorize training examples

Why people make it: If a network gets 100% on training data, it can seem "done."

Correct understanding: The seven challenges (viewpoint, scale, deformation, occlusion, illumination, clutter, intra-class variation) mean the classifier must generalize far beyond memorized examples to perform well on the independent testing set.

Concept Map

Glossary

Class Imbalance
When some categories have far more training examples than others, biasing the classifier toward the over-represented classes.
CNN (Convolutional Neural Network)
An end-to-end deep learning architecture that learns its own filters from raw pixel data, skipping hand-engineered feature extraction.
Data Point
A single example/item in a dataset — one image, in the case of image classification.
Dataset
A collection of data points used to extract knowledge via machine learning.
End-to-End Model
A model (like a CNN) that takes raw input data directly and produces output, without a separate hand-engineered feature extraction step.
F-measure
An aggregate metric (combining precision and recall) used to quantify classifier performance.
Feature Extraction
In the traditional pipeline, a step between splitting and training data where hand-engineered algorithms (HOG, LBPs) quantify aspects of an image such as shape, color, or texture.
Ground-Truth Labels
The actual, correct category labels for the testing set, used to check the classifier's predictions.
HOG (Histogram of Oriented Gradients)
A hand-engineered feature extraction algorithm used in traditional image classification.
Hyperparameters
Tunable settings of a network (learning rate, decay, regularization, etc.) that must be set properly, typically using a validation set.
Image Classification
The task of assigning a label to an image from a predefined set of categories.
LBPs (Local Binary Patterns)
A hand-engineered feature extraction algorithm used in traditional image classification, often for texture.
Precision
An evaluation metric quantifying how many of the classifier's positive predictions were correct.
Recall
An evaluation metric quantifying how many of the actual positive cases the classifier correctly identified.
Testing Set
Data held out from training, used only to evaluate final classifier performance.
Training Set
Data used by the classifier to learn category patterns, correcting itself when predictions are wrong.
Validation Set
A subset of the training data (~10–20%) used as "fake test data" to tune hyperparameters before final evaluation.

🚀 5-Minute Revision

  • Image classification = assign a label to an image from a fixed category set; to a computer, an image is a W × H × 3 grid of numbers.
  • Seven challenges: viewpoint, scale, deformation, occlusion, illumination, background clutter, intra-class variation.
  • Why rules don't work: you can't hand-write if/else logic to tell a cat from a dog — deep learning learns the rules instead.
  • Four-step pipeline: 1) Gather Dataset (watch class imbalance) → 2) Split Dataset (train/validation/test, never overlap) → 3) Train Network → 4) Evaluate (precision, recall, f-measure).
  • Validation set (~10–20% of training data) tunes hyperparameters — the testing set is touched only once, at the end.
  • Feature-based ML = hand-engineered features (HOG, LBPs) + classifier. Deep learning (CNN) = end-to-end, learns its own filters from raw pixels — powerful, but non-trivial to train.

🧠 If You Remember Only One Thing...

You cannot hand-write rules to recognize a cat versus a dog — so image classification replaces rule-writing with a disciplined data pipeline (gather → split → train → evaluate) where the network itself learns what matters, whether from hand-picked features or, in the case of CNNs, straight from the raw pixels.
